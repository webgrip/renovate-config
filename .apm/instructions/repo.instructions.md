# AGENTS.md — webgrip/renovate-config

The preset table and the consumer `extends` snippets are in [`README.md`](https://forgejo.webgrip.dev/webgrip/renovate-config/src/branch/main/README.md). This file
carries the things a JSON preset cannot tell you.

## Shape

Every JSON file at the repo root except `package.json`, `package-lock.json` and `renovate.json`
is a published preset; `scripts/published.cjs` is that list, and validation, the release paths
filter and the release assets all read it. `default.json`, `review-non-major.json`,
`automerge-non-major.json`, `first-party.json`, the gates `reviewed.json` and `unattended.json`,
and the `profile-*.json` names for them are generated by `npm run generate` from `parts/` and the
hand-written overlays, as `scripts/presets.mjs` lists; edit a part, never a generated file.
`docs/policy.md` is generated the same way, by resolving each gate with Renovate's own code; its
diff in a pull request is the behaviour change. `package.json` is `private: true` and exists only to pin the
Renovate CLI for validation and to drive semantic-release — **nothing here is published to a
registry**.

## Gate, risk tier, capability

[ADR 0001](https://forgejo.webgrip.dev/webgrip/renovate-config/src/branch/main/docs/adr/0001-gates-risk-tiers-and-capabilities.md) keeps three questions apart. The
gate (`reviewed` or `unattended`) is per repository and is the only policy difference between the
two gate presets. The risk tier is per dependency and lives in `parts/risk-tiers.json`, which both
gates carry. A capability overlay (`apm.json`, `golang.json`, `docker-arg-pins.json`) only teaches
detection: it must not set `groupName`, `groupSlug`, `automerge`, `dependencyDashboardApproval`,
`minimumReleaseAge` or `rebaseWhen`, and `npm test` fails when it does. A group or gate decision
goes into a part instead. `gitops.json` is the exception for now, because of its external
`home-operations` presets.

## Consumers resolve presets from Forgejo

Consumers extend `local>webgrip/renovate-config:<preset>#vX.Y.Z`. The self-hosted Renovate runs
on the Forgejo platform, so `local>` reads the tag from Forgejo, which also cuts it. A preset
change is live for a consumer once the tag exists and the consumer's pin reaches it; Renovate
bumps that pin in a branch that merges itself. A repository Renovate runs against on GitHub
extends `github>` instead and reads the GitHub mirror, which lags the tag by a mirror sync.
Adding a new preset file means the consumers' `extends` line has to name it — a file that nobody
extends is dead weight.

Pin releases; do not tell a consumer to extend `#main`.

## Validation is the gate

`npm run validate` runs `renovate-config-validator --strict` over every published preset, and
`npm test` checks that generated files are current and that each profile applies the policy in
`docs/profiles.md`, using Renovate's own rule matching.
`--strict` rejects unknown and deprecated fields, so a config option that Renovate has since
renamed fails here rather than silently doing nothing in a consumer.

## Per-preset notes worth knowing

- **`default.json` is deliberately strict**: dashboard approval, pinned ranges, low concurrency,
  delayed releases, no automerge. Loosening it changes every consuming repo at once; loosen in
  an overlay instead. The one exception is this preset itself: a `webgrip/renovate-config` bump
  merges on green with no tick and no soak, because a consumer waiting on a tick is a policy fix
  that has not landed.
- **`forgejo.json` uses `force:`, which is admin-level, and that is intentional.** Forgejo
  Actions run on `pull_request`, so a Renovate branch commit that has no pull request yet has no
  commit status: `GET /commits/{sha}/status` comes back empty, `not-pending` never resolves, and
  PRs hang for the full `prNotPendingHours`. Once the pull request exists its jobs do report
  there, which is what an automerging overlay reads. Consumers extend `:default` at repo
  level, which only a `force` override beats.
- **`golang.json`** exists because Renovate leaves indirect Go modules unmanaged by default; it
  also tidies `go.mod`/`go.sum` in-branch and rewrites `/vN` import paths. Its groups live in
  `parts/go-module-groups.json`, which `default` and both gates carry.
- `safe-automerge.json` automerges digest updates and low-risk Actions updates only. Widening
  what it automerges is a decision, not a tweak.
- **`automerge-non-major.json` is that decision, made opt-in**: every minor, patch, digest and
  pin update in one branch that merges itself on green, with the release-age soak restored and
  `rebaseWhen: conflicted`. It uses Renovate's own automerge, not the platform's, because
  Forgejo's merge-when-checks-succeed merges at once on a branch without required checks. The
  generator appends the preset-bump part last, so its soak and grouping do not catch it.

## Release traps

- `chore(deps)` / `build(deps)` cut a patch; a dependency **major** is not a product-breaking
  change and must not cut a major here.
- Releases and promotion PRs run as the `webgrip-ci` bot, with `WEBGRIP_CI_TOKEN` — never
  `secrets.FORGEJO_TOKEN`, which resolves to the built-in per-job token.
- `open_promotion_pr.yml` is inert until a `next` branch exists; it talks to the Forgejo REST
  API because `gh` is GitHub-only.
- **checkout and setup-node majors move deliberately, never on automerge.** The old "v6 is broken on non-GitHub runners" rule was disproven on 2026-09-18 by a canary on the real Forgejo runner ([homelab-cluster run 1710](https://forgejo.webgrip.dev/webgrip/homelab-cluster/actions/runs/1710)): checkout v6 and v7 and setup-node v5, v6 and v7 all pass.

## Repo rules

- **Comments are NOT allowed.** Always communicate intent with code: a precise name, a type, a
  smaller function, a test that states the case. A comment is a failure. This holds for every
  language in the repo, prose in YAML and TOML included. Machine-read directives stay, because the
  toolchain acts on them as syntax: `// @ts-check`, `eslint-disable`, `<!-- prettier-ignore -->`,
  `# syntax=`, `# renovate:`, `# yaml-language-server:`, and shebangs. Doc-comment forms the
  toolchain itself reads are not comments either and stay: godoc directly above an exported
  identifier, rustdoc `///` and `//!`, and PHPDoc blocks carrying type tags. Anything that outlives
  a single expression belongs in `docs/` or an ADR, where it gets reviewed, linked and kept
  current. The estate decision is
  [ADR 0006](https://forgejo.webgrip.dev/webgrip/workflows/src/branch/main/docs/adrs/0006-no-comments-in-code.md).

Renovate presets are JSON, which has no comment syntax; the `description` field is the
documented place for intent and every preset here already uses it.
