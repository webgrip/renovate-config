# webgrip/renovate-config

Shared, versionable Renovate presets for Webgrip repositories.

## Quick start

Prefer pinning to a release tag in consuming repositories:

```json
{
  "extends": ["github>webgrip/renovate-config#v1.2.1"]
}
```

Add opt-in overlays when a repository needs them:

```json
{
  "extends": [
    "github>webgrip/renovate-config#v1.2.1",
    "github>webgrip/renovate-config:grouped#v1.2.1",
    "github>webgrip/renovate-config:safe-automerge#v1.2.1",
    "github>webgrip/renovate-config:gitops#v1.2.1",
    "github>webgrip/renovate-config:golang#v1.2.1"
  ]
}
```

## Profiles

A repository takes one profile, in one line of its `renovate.json`:

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["local>webgrip/renovate-config:profile-app#vX.Y.Z"]
}
```

| Profile | For | Minor, patch, pin | Digests, CI actions | Security fixes | Majors | Webgrip's own |
| --- | --- | --- | --- | --- | --- | --- |
| `profile-app` | services and products | one grouped pull request, opens without a tick, a person merges | merge themselves on green | merge themselves on green | dashboard tick | merge themselves on green, majors too |
| `profile-site` | static sites | same as `profile-app` | same | same | same | merge themselves on green, majors too |
| `profile-library` | packages, presets, reusable workflows and actions | one grouped branch that merges itself on green after a soak | merge themselves | merge themselves | dashboard tick | merge themselves on green, majors too |
| `profile-image-set` | repositories of container images | as `profile-library`, plus Dockerfile `ARG` pins under a `# renovate:` line | merge themselves | merge themselves | dashboard tick | merge themselves on green, majors too |

A profile is one self-contained file, generated by `npm run profiles` from the presets listed in `scripts/profiles.mjs`, merged with Renovate's own `mergeChildConfig`. Edit a building block, not a profile file, and regenerate. Profiles are self-contained because a preset that extends another preset of this repository fetches it from the default branch, not from the tag the consumer pinned. `npm test` fails when a profile file is out of date, and it checks the policy in the table above by resolving each profile and applying its rules with Renovate's own code. A repository adds overlays such as `golang` after its profile, or rules of its own.

Webgrip's own dependencies (`webgrip/*`, `@webgrip/*`, the skills and packs pinned through the `apm` preset, `harbor.webgrip.dev/webgrip/*`) share one branch that merges itself on green, majors included, without a tick or a soak: their releases are reviewed where they are made. Every profile ends with `own-automerge`; a repository on another preset adds `local>webgrip/renovate-config:own-automerge#vX.Y.Z` last.

GitOps repositories keep `default` plus `gitops`. A generated gitops profile would have to inline the external `home-operations` presets that `gitops` extends, because a self-contained file cannot keep an external preset's rules in their original order.

## Available presets

| Preset | Purpose |
| --- | --- |
| `github>webgrip/renovate-config` | Strict default: dashboard approval, pinned ranges, low concurrency, delayed releases, no automerge |
| `github>webgrip/renovate-config:grouped` | Opt-in overlay to group non-major updates into fewer PRs |
| `github>webgrip/renovate-config:automerge-non-major` | Opt-in overlay for repositories whose CI is the gate: minor, patch, digest and pin updates in one branch that merges itself once checks are green, with the release-age soak restored; majors and Go toolchain minors keep the dashboard tick; preset bumps merge themselves in their own branch |
| `github>webgrip/renovate-config:own-automerge` | Webgrip's own dependencies merge themselves on green, majors included, in one `webgrip packages` branch without a tick or a soak; every profile ends with it, other configs add it last |
| `github>webgrip/renovate-config:safe-automerge` | Opt-in overlay to automerge only digest updates and low-risk GitHub Actions updates after checks pass |
| `github>webgrip/renovate-config:gitops` | Opt-in GitOps overlay that composes selected `home-operations/renovate-presets` for Kubernetes/Flux/OCI/Talos/CNPG/Grafana extraction plus Webgrip-specific GitOps PR polish |
| `github>webgrip/renovate-config:golang` | Opt-in Go overlay: manages indirect Go modules (off by default in Renovate), tidies go.mod/go.sum in-branch, rewrites `/vN` import paths, and labels toolchain moves |
| `github>webgrip/renovate-config:review-non-major` | Opt-in overlay: minor, patch and pin updates share one pull request that opens without a dashboard tick and waits for a human merge, with the release-age soak restored |
| `github>webgrip/renovate-config:security-automerge` | Opt-in overlay: security fixes from OSV alerts merge themselves once checks are green |
| `github>webgrip/renovate-config:docker-arg-pins` | Opt-in overlay: Dockerfile `ARG` image and tool pins under a `# renovate: datasource=… depName=…` line |

## Repo standards

- `CODEOWNERS` routes reviews to `@webgrip/infrastructure`
- CI validates every shared preset on every PR and push to `main`
- Example consumer configs live in `examples/`
- This repo dogfoods its own preset via `renovate.json`

The GitOps overlay extends selected presets from [`home-operations/renovate-presets`](https://github.com/home-operations/renovate-presets), which is Apache-2.0 licensed. See [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

Detailed guidance lives in [`docs/renovate.md`](docs/renovate.md).
