# webgrip/renovate-config

Shared, versionable Renovate presets for Webgrip repositories.

## Quick start

Prefer pinning to a release tag in consuming repositories:

```json
{
  "extends": ["local>webgrip/renovate-config#vX.Y.Z"]
}
```

Add opt-in overlays when a repository needs them:

```json
{
  "extends": [
    "local>webgrip/renovate-config#vX.Y.Z",
    "local>webgrip/renovate-config:grouped#vX.Y.Z",
    "local>webgrip/renovate-config:safe-automerge#vX.Y.Z",
    "local>webgrip/renovate-config:gitops#vX.Y.Z",
    "local>webgrip/renovate-config:golang#vX.Y.Z"
  ]
}
```

## Profiles

A repository takes one profile, in one line of its `renovate.json`:

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["local>webgrip/renovate-config:profile-app#vX.Y.Z"]
}
```

| Profile | For | Third-party minor, patch, pin | Digests, CI actions | Webgrip's own minor, patch, digest, pin | Security fixes | Majors |
| --- | --- | --- | --- | --- | --- | --- |
| `profile-app` | services and products | one grouped pull request after a soak, a person merges | one branch of their own, merges itself on green | one branch of their own, no soak, merges itself on green | merge themselves on green | dashboard tick |
| `profile-site` | static sites | same as `profile-app` | same | same | same | same |
| `profile-library` | packages, presets, reusable workflows and actions | one grouped branch that merges itself on green after a soak | in that grouped branch | same | same | same |
| `profile-image-set` | repositories of container images | as `profile-library`, plus Dockerfile `ARG` pins under a `# renovate:` line | in that grouped branch | same | same | same |

[The policy table](docs/policy.md) shows what every profile does with each kind of update; it is generated from the presets, so a pull request that changes behaviour changes that table. [What each profile does, and why](docs/profiles.md) gives the reasons and the decisions that stay open.

Every preset file at the repository root is published, validated and released; `scripts/published.cjs` is that list. Profiles and the presets that share their rules (`default`, `review-non-major`, `automerge-non-major`, `first-party`) are generated by `npm run generate` from the parts in `scripts/presets.mjs`, merged with Renovate's own `mergeChildConfig`. Edit a part, not a generated file, and regenerate. Generated files are self-contained because a preset that extends another preset of this repository fetches it from the default branch, not from the tag the consumer pinned. `npm test` fails when a generated file is out of date, and it checks the policy table in the docs by resolving each profile and applying its rules with Renovate's own code. A repository adds overlays such as `golang` after its profile, or rules of its own.

GitOps repositories keep `default` plus `gitops`. A generated gitops profile would have to inline the external `home-operations` presets that `gitops` extends, because a self-contained file cannot keep an external preset's rules in their original order.

## Available presets

| Preset | Purpose |
| --- | --- |
| `local>webgrip/renovate-config` | Strict default: dashboard approval, pinned ranges, low concurrency, delayed releases, no automerge |
| `local>webgrip/renovate-config:grouped` | Opt-in overlay to group non-major updates into fewer PRs |
| `local>webgrip/renovate-config:automerge-non-major` | Opt-in overlay for repositories whose CI is the gate: minor, patch, digest and pin updates in one branch that merges itself once checks are green, with the release-age soak restored; majors and Go toolchain minors keep the dashboard tick; preset bumps merge themselves in their own branch |
| `local>webgrip/renovate-config:safe-automerge` | Opt-in overlay to automerge only digest updates and low-risk GitHub Actions updates after checks pass |
| `local>webgrip/renovate-config:gitops` | Opt-in GitOps overlay that composes selected `home-operations/renovate-presets` for Kubernetes/Flux/OCI/Talos/CNPG/Grafana extraction plus Webgrip-specific GitOps PR polish |
| `local>webgrip/renovate-config:golang` | Opt-in Go overlay: manages indirect Go modules (off by default in Renovate), tidies go.mod/go.sum in-branch, rewrites `/vN` import paths, and labels toolchain moves |
| `local>webgrip/renovate-config:review-non-major` | Opt-in overlay: minor, patch and pin updates share one pull request that opens without a dashboard tick and waits for a human merge, with the release-age soak restored |
| `local>webgrip/renovate-config:first-party` | Opt-in overlay: minor, patch, digest and pin updates of Webgrip's own packages share one branch that opens without a tick, skips the soak and merges itself on green; every profile includes it |
| `local>webgrip/renovate-config:security-automerge` | Opt-in overlay: security fixes from OSV alerts merge themselves once checks are green |
| `local>webgrip/renovate-config:docker-arg-pins` | Opt-in overlay: Dockerfile `ARG` image and tool pins under a `# renovate: datasource=… depName=…` line |

## Repo standards

- `CODEOWNERS` routes reviews to `@webgrip/infrastructure`
- CI validates every shared preset on every PR and push to `main`
- Example consumer configs live in `examples/`
- This repo dogfoods its own preset via `renovate.json`

The GitOps overlay extends selected presets from [`home-operations/renovate-presets`](https://github.com/home-operations/renovate-presets), which is Apache-2.0 licensed. See [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

Detailed guidance lives in [`docs/renovate.md`](docs/renovate.md).
